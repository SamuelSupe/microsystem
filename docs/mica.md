# Mica scripting runtime

Mica is the small, capability-brokered scripting runtime shipped as the static
`bin/mica` ELF in bootfs. It is deliberately a language/runtime slice, not a
POSIX shell or a general-purpose dynamic linker.

## Current acceptance

The final OrbStack run recorded in
`target/unified-fp-simd-final.log` passed the Mica host suite
(`24/24`) and the QEMU Mica stage. The stage exercises an inline eval (`42`),
the interactive REPL (`print(6 * 7)` → `42`), a file script with arguments,
module caching, filesystem denial, atomic fsync, DNS, TCP, UDP and HTTP, and
rejects `run mica` because Mica sessions use the script broker rather than the
ordinary application loader. The unified stage explicitly sets
`MICROSYSTEM_MICA_TLS_FIXTURE=1`; it observed the trusted body `mica-https-ok`,
a presented root-chain, P-384 `CertificateVerify` and a long CA DNS name, and
rejected unknown-CA, expired, not-yet-valid and hostname-mismatch certificates.

## Language

The lexer/compiler currently implements:

- `nil`, booleans, signed decimal and hexadecimal integers, floating-point
  literals, UTF-8 source strings with the small escape set (`\\n`, `\\r`, `\\t`,
  `\\\\`, `\\'`, `\\"`), and table literals;
- local declarations, assignment, multiple return values, anonymous and named
  functions with lexical captures, chained `if`/`elseif`/`else` branches,
  `while`, numeric and table iteration `for`, `break`, `return`, semicolons,
  indexing, field access, method calls, and calls with multiple
  arguments/returns;
- arithmetic (`+ - * / // %`), comparisons, equality, short-circuit `and`/`or`
  and `not`.

The VM supplies `type`, `tostring`, `assert`, `error`, `pcall` and `require`.
Tables are ordered key/value vectors; values are `nil`, boolean, integer,
number, string, bytes, table or function. Errors returned by a broker call are
tables with `kind`, `message`, `operation` and numeric `code` fields.

## VM and limits

| Resource | Limit | Enforcement |
| --- | ---: | --- |
| source passed to `compile` | 64 KiB | compiler rejects larger input |
| one loaded module | 64 KiB | `require` read limit |
| total module source per session | 256 KiB | module cache accounting |
| generated bytecode | 128 KiB | compiler size check |
| call frames | 128 | `VmError::CallDepth` |
| operand stack | 4,096 values | `VmError::StackOverflow` |
| VM heap accounting | 512 KiB by default | mark/sweep accounting |
| instructions | 10,000,000 by default | `VmError::InstructionLimit` |
| wall time | 10 s by default; 5 s for REPL | `VmError::Timeout` |
| cooperative yield | every 4,096 instructions | `Host::yield_now` |

The collector marks reachable closures and table graphs, sweeps unreachable
closures, then recomputes reachable string/bytes/table storage. `pcall` catches
script/runtime errors, but instruction, timeout, interrupt, stack, call-depth
and heap failures remain VM outcomes. A file session has an 8 KiB argument ring,
a 32 KiB output/broker ring and a 16-page (64 KiB) per-process session region at
`0x0058_0000`; file sources are read from MFS after the manifest prefix rather
than copied into the small inline source field.

The kernel-side layout is separate from VM accounting: the kernel heap is
64 MiB; every ordinary EL0 address space has a 64 KiB stack, a 1 MiB user heap,
and a `0xe0000`-byte Mica/task image window. The Mica process is an ordinary
`ThreadStartEx` application (dynamic PID range starts at 14), not a resident
service slot.

The shell and SSH launchers parse `--timeout` from `1ms` through `24h`.
Non-GUI eval, REPL and file sessions are hard-capped at 60 seconds even when a
larger value is requested; GUI file sessions may use up to 24 hours. Defaults
remain 10 seconds for file scripts and 5 seconds for REPL evaluation.

## Permissions and session construction

Scripts begin with `--!mica 1`. File scripts may then declare
`--!allow ...` directives before the first non-comment statement. Rules are
normalized and exact in scope:

```text
fs.read:/data                 # path prefix, absolute and normalized
fs.write:/data/output
net.connect:example.test:443  # exact host and port; no wildcard
net.browse                    # bundled Reader HTTP/HTTPS GET path
proc.list
proc.spawn:counter
proc.kill:counter
sys.stats
random                        # random source
gui.window                   # one retained GUI window (file mode only)
```

`fs.read`/`fs.write` are path-prefix permissions. `net.connect` remains a
case-insensitive exact host/port rule. `net.browse` is an unscoped permission
used by the bundled Reader for HTTP/HTTPS GET requests to a dynamic host; it
does not grant raw `net.resolve`, TCP or UDP calls and it does not authorize
POST, PUT, PATCH or DELETE. Those operations continue to require their exact
`net.connect:host:port` rules. Process permissions name the program;
`proc.list`, `sys.stats` and `random` are unscoped. Invalid paths, `..` escaping
the root, NULs, wildcards and malformed rules are rejected.

For an eval or REPL, the launcher policy is the effective policy. For a file
session, the Mica manifest is intersected with that launcher policy. The init
broker creates an isolated session `FrameRegion`, a notification, and only the
following capabilities are passed to the Mica task:

| Capability | Rights in Mica | Purpose |
| --- | --- | --- |
| session region | `READ|WRITE|MAP|GRANT` | session header and broker rings |
| notification | `READ|WRITE` | REPL/input completion |
| filesystem endpoint | `WRITE` | file broker |
| network endpoint | `WRITE` | netd broker |
| random source | `READ` | `random.*` and TLS RNG |
| system info (optional) | `READ` | `sys.stats` only when allowed |

The desktop Reader entry is fixed in init: its bundled path, manifest and
launcher policy contain `gui.window`, `net.browse` and `fs.write:/data`. A GUI
client cannot replace that path or broaden the policy through the launcher
endpoint.

GUI file sessions additionally receive a 64 KiB command `FrameRegion`, a 4 KiB
event `Frame` and a dedicated GUI endpoint. These are installed atomically by
`ThreadLaunchV2`; `ThreadLaunchV1` remains compatible for non-GUI sessions. The
Mica task still receives no framebuffer, GPU/BAR, input, DMA or IRQ capability.

The desktop launcher is a fixed five-icon registry (Terminal id 1, Files id 2,
Monitor id 3, Reader id 4 and Editor id 5), owned by init rather than by Mica or the display-list
`Icon` command. Built-in icons focus/restore their existing windows. Reader and
Editor clicks send only their application id over the init-owned endpoint;
windowd deduplicates active/pending requests and init maps each id to a fixed
script path, manifest and entry policy. A dynamic GUI registration carries the
application id in registration word 3. Thus effective permissions remain the
manifest ∩ launcher `--allow` ∩ entry-policy intersection, and an icon click
cannot select an arbitrary path or broaden capabilities.

The script broker owns the token and checks the same policy before process
list/spawn/wait/kill. Mica receives no raw device, MMIO, block, IRQ,
framebuffer or GPU capability; GUI sessions receive only the validated command,
event and endpoint capabilities described above.

| `bytes` | `from_string`, `to_string`, `len` |
| `table` | `len`, `insert`, `remove`, `next` |
| `math` | `abs`, `floor`, `ceil`, `min`, `max` |
| `fs` | `stat`, `list`, `open`, `read`, `write`, `fsync`, `close`, `read_file`, `write_file`, `mkdir`, `rename`, `unlink`, `sync` |
| `proc` | `list`, `spawn`, `wait`, `kill` |
| `time` | `uptime`, `sleep`, `realtime` |
| `sys` | `version`, `stats` |
| `random` | `bytes`, `int` |
| `net` | `resolve`, `tcp_connect`, `tcp_read`, `tcp_write`, `tcp_close`, `udp_open`, `udp_send_to`, `udp_recv_from`, `udp_close`, `tls_connect`, `cancel` |
| `http` | `request`, `get`, `post`, `put`, `patch`, `delete` |
| `io` | `read`, `write`, `flush` |
| `args` | `get`, `all` |

Filesystem writes support atomic temporary-file/rename and optional `fsync`.
`fs.stat(path)` returns type, size, mode, uid, gid and modified (Unix seconds).
Mode contains only permission bits; missing timestamp information is zero.
`read_file` defaults to 64 KiB and accepts at most 256 KiB. Broker transfers
are capped at 32 KiB per request. `proc.spawn` is policy-owned and only starts
static bootfs application ELFs; Mica itself is intentionally not a valid
ordinary `run` target.

`net.resolve` performs an A query through netd. TCP and UDP are explicit
connection/socket APIs; operations yield on `Busy` and time out after the
broker deadline. HTTP supports `http://` and `https://`, methods GET/POST/PUT/
PATCH/DELETE, caller headers, `Content-Length` and chunked response decoding.
For the bundled Reader, `net.browse` gates only its `http.get` GET path and
allows the host to be selected at runtime; raw resolve/TCP/UDP and every
non-GET method still require exact `net.connect:host:port` permission. Headers
are limited to 16 KiB, requests to 32 KiB, and `read_all()` defaults to 1 MiB
(maximum 4 MiB). The generic HTTP API returns a 3xx response as-is and does
not follow `Location`. The response table exposes the
first `Content-Type` value (maximum 256 bytes) as `content_type` and the first
`Location` value (maximum 2,048 bytes) as `location`; arbitrary response
headers are not exposed.

## Network and TLS boundary

`netd` is the only task with the kernel `NetworkDevice` read/write capability.
Kernel network syscalls 27/28 reject every other task; Mica receives only a
write-only `NETWORK_ENDPOINT`. netd owns the raw VirtIO-net path, smoltcp
Ethernet/TCP/UDP sockets, and DNS. The final marker is:

```text
[net] netd ready ipv4=10.0.2.15 outbound=true raw-device-isolated=true tcp-owner=true dns=true tcp=64 udp=8
```

The guest uses `10.0.2.15/24`, gateway `10.0.2.2`, DNS server
`10.0.2.3:53`, eight script sessions, eight logical connections per session,
64 outbound TCP slots and eight UDP slots. Every session has an isolated
broker region; Mica policy still gates the destination host/port.

`net.browse` does not change the raw network boundary. The HTTP implementation
uses a private broker marker while it performs the GET's DNS/TCP exchange;
user-visible `net.resolve`, `net.tcp_connect` and UDP calls cannot set that
marker and remain exact-permission operations. The HTTP URL parser accepts an
ASCII host up to 253 bytes, rejects user-info/wildcards and malformed labels,
preserves the query, and removes a fragment before sending the request.

`net.tls_connect` is deliberately a low-level **NotSupported** operation. The
trusted HTTPS path is implemented inside the Mica runtime: it calls netd TCP,
uses TLS 1.3, checks the certificate chain, validity time and hostname, and
verifies RSA-PSS plus ECDSA P-384 `CertificateVerify` signatures. If a server
presents the selected trust anchor again as the final chain entry, the
verifier omits that redundant tail before chain validation while retaining the
anchor. TLS uses the PL031-backed `ClockRealtime` syscall (ABI 31) and the
kernel rejects an unavailable/invalid RTC value.

The production trust store is an MCAB bundle with a pinned Mozilla-derived
snapshot and a build-time host-trust extension:

```text
magic/version: MCAB / 1
pinned snapshot roots: 121
pinned snapshot bytes: 129643
pinned snapshot sha256: 328fa09c4231bdf284b873b2b1e19c82901e12293960a4f9f1ea939ab7cca2b6
path: /.system/certs/ca-bundle.derpack
```

Host-extension counts, bytes and hashes are build-run evidence rather than a
stable Mica API; the final values are recorded in the documentation result.
Before compiling the Mica service, `xtask` generates the guest bundle from the
pinned 121-root snapshot and the build container's `SSL_CERT_FILE`, appending
only deduplicated host certificates. Each appended certificate is capped at
16 KiB and the complete bundle at 256 KiB. The build injects the full bundle
SHA-256 into the Mica service; at runtime every process verifies the MCAB
header, count, exact payload and complete-bundle hash before using the exact
trusted MFS path with the trusted-read marker. The CA bytes are not obtained
from a shared GUI or generic `FrameRegion`; the per-process session region is
only transient broker storage. HTTPS response data is buffered (about 1 MiB by
default; TLS record accounting permits a small header/record allowance), so it
is not a streaming API.

The complete TLS fixture gate observed a trusted TLS 1.3 response body
`mica-https-ok` and rejected `unknown-ca`, `expired`, `not-yet-valid` and
`hostname-mismatch`. `net.browse` uses this same TLS roots/time/hostname
validation path; the permission only changes destination authorization for
GET. This is a runtime HTTPS guarantee, not a claim that the low-level
`net.tls_connect` broker opcode is implemented.

## GUI sessions and widgets

GUI execution is deliberately file-only:

```text
mica --gui --timeout 86400s --allow gui.window /mica/gui-counter.mica -- arg1 arg2
```

`-e` and REPL sessions cannot request GUI. A GUI file must declare
`--!allow gui.window`; effective access is the intersection of that manifest,
the launcher's `--allow gui.window` rule and the entry-point policy. SSH uses
the maximum policy in `/.system/ssh/mica-policy`. If GPU/windowd is absent the
launcher returns `NotSupported`.

`require("gui")` exposes a retained toolkit with up to four windows per script:

```text
window, label, button, text_input, checkbox, list, scroll,
row, column, spacer, canvas
```

Window methods are `set_root`, `set_title`, `invalidate`, `run` and `close`.
Widgets support `set_text`, `set_checked`, `set_items` and callbacks
`on_click`, `on_change`, `on_submit` and `on_select`; `set_callback` can attach
or clear the same callbacks after construction. Row/column/scroll use
bounded integer flex layout with `padding`, `gap`, fixed dimensions and `grow`.
Scroll handles bounded wheel scrolling but is not a focus/click target. List and
Canvas own their own client clips; Canvas is limited to the six validated GUI
drawing commands. Each window owns its widget tree and display sequence;
cross-window widget sharing and stale widget handles are rejected. `window:run()`
dispatches events and callbacks for all session windows and returns when that
window closes. Close requests for the last window allow two seconds of cleanup
before init reclaims a nonresponsive session. A window can be created again
after another closes without retaining the old widget resources.

Focused text inputs support Left/Right and Home/End caret movement,
Backspace/Delete by UTF-8 character, and Ctrl+A whole-field selection. Typing
replaces that selection. Clicking focuses the field at its end; Tab cycles
focus and Enter submits. Ctrl+C/X/V copies/cuts/pastes a Ctrl+A selection using
the shared 4 KiB UTF-8 clipboard; `gui.clipboard.read()` and `.write(text)` expose
the same store. Ctrl+Space toggles dictionary Pinyin composition, with a visible
preedit/candidate overlay, Space/Enter or number-key selection, Backspace and
Escape cancellation. See `docs/gui.md` for dictionary limits and configuration.
Pointer-positioned caret placement and partial selection are not implemented.

The host is connected to windowd with `protocol::GUI = 6`: a 64 KiB command
FrameRegion, a 4 KiB event Frame, a dedicated endpoint and
`script::EVENT_GUI`. Windowd validates UTF-8, command bounds, clip, payload
hash and damage rectangles, then atomically swaps the display list. It accepts
up to 4,096 commands, 48 KiB text and 16 damage rectangles; validated damage
rectangles bound redraws, merged at up to 60 Hz. The six commands are `Clear`, `FillRect`, `StrokeRect`, `Text`,
`Icon` and `SetClip`; events include pointer, button, wheel, key, text input,
focus, configure, expose and close. Unifont is loaded from
`/.system/fonts/unifont-17.0.05.ufb` with a bounded 128-entry cache and
ASCII/replacement fallback. The cache is 2-way set-associative; Mica never receives framebuffer/GPU/input/DMA/BAR/IRQ
capabilities.

Windowd merges overlapping damage, culls clean display-list command/text/glyph
work, and redraws only local `DesktopVisual` windows for drag, resize, focus and
Terminal updates. Input is batched at 16 events. These renderer changes leave
the GUI ABI, permissions and endpoint protocol unchanged; OrbStack QEMU TCG is
functional/regression evidence rather than a native performance benchmark.

## Mica Reader example

The MFS1 example `/.system/examples/mica/browser.mica` is a small, deliberately
restricted document reader built entirely with the Mica GUI and HTTP modules:

```text
mica --gui --timeout 86400s --allow gui.window \
  --allow net.browse --allow fs.write:/data \
  /.system/examples/mica/browser.mica -- https://example.com/
```

The script owns one 760x620 window with address, back/forward/reload and Go
controls, a save-path field and Save button, a paged document list, and
previous/next page controls. It uses `http.get`, accepts response bodies up to
98,304 bytes, and renders at most 96 logical lines of 64 characters, with 18
lines per page. It accepts UTF-8 `text/plain` and `text/html`; other content
types and invalid UTF-8 are reported in the document. The HTML reader is a
bounded state-machine subset:
`head`/`title`, `p`, `div`, `h1`-`h3`, `li`, `pre`, `a`, `br`, comments, and entity
decoding. Script and style bodies are skipped; JavaScript, CSS, images, forms,
cookies, automatic downloads, and persistent browsing history are not
implemented. The Save control writes the raw response body to a chosen `/data`
file only after an explicit click. Its editable path defaults to
`/data/reader.html`; each save is limited to 32,512 bytes and uses atomic
replacement with fsync.

Links may be absolute, root-relative, or same-origin relative paths. A page
link whose origin differs from the current page is rejected; a user can still
enter a different HTTP(S) origin explicitly in the address field. Fragments
are removed before a request is sent, and a non-HTTP(S) scheme is rejected.
The Reader follows up to eight HTTP(S) redirects, resolving absolute and
relative `Location` values against the current URL. A redirect may select a
different host because the bundled app already has unscoped `net.browse`; page
links remain same-origin, and the HTTP library itself still returns raw 3xx
responses. Back/forward history and reload are local in-memory state; a failed
back/forward request leaves the history cursor and address on the current
entry. The Save operation uses the Reader's `fs.write:/data` grant; the
filesystem grant does not include file reads, raw DNS/TCP/UDP or non-GET
methods. Exact
`net.connect:host:port` rules remain the path for those network operations.

The HTTP response table includes bounded `content_type` (at most 256 bytes) and
`location` (at most 2,048 bytes) fields in addition to `status`,
`content_length`, `chunked`, `complete`, and `read_all`. The browser uses these
fields without exposing arbitrary headers. String helpers used by the example
are `find`, `trim`, `starts_with`, `ends_with`, `replace`, and
`collapse_space`; GUI widgets support `set_callback` for `click`, `change`,
`submit`, and `select` handlers.

The targeted OrbStack Mica host suite passes `24/24`, including browser source
compilation, UTF-8 string operations, chained `elseif`, short-circuit boolean
operators, closure callback state, and GUI `set_callback`. The GUI browser
fixture served one `GET /index.html` and one `GET /next.html`, with no `evil`
request; the Reader loaded both with status 200. The separate network fixture
observed `GET /index.txt?browse=1` after stripping `#fragment`, and the combo
marker records `browse=true`, raw resolve/TCP/UDP and POST denials, plus the
trusted HTTPS body and all four TLS rejection cases. The Reader sets a visible
Loading status and calls `app:present()` before blocking `http.get`; its parser
caches `source_length`. Its endpoint 1 registered, presented, reclaimed, and
exited with status 0. Refresh-run screenshot CRCs were `2286d988` (pre),
`5dab179e` (same-origin link), and `f60453d9` (cross-origin rejection). The
browser evidence is in `target/unified-browser-public-internet-final.log`,
`target/unified-browser-public-internet-fsck.log`, `target/gui-browser-fixture.log`,
and `target/mica-dns-fixture.log`.
Those recorded runs predate automatic redirects and the Save control; they do
not validate either behavior.
The public capture [`target/browser-internet-reader-imagebound-final.png`](../target/browser-internet-reader-imagebound-final.png)
shows `https://example.com/` with `HTTP 200 — https://example.com` and
`# Example Domain`.

## Mica Editor example

The MFS1 example `/.system/examples/mica/editor.mica` is a bounded text
editor built from the same GUI and filesystem brokers:

```text
mica --gui --timeout 86400s --allow gui.window --allow fs.read:/data \
  --allow fs.write:/data /.system/examples/mica/editor.mica -- /data/note.txt
```

It owns one window containing a path field, Open/Save As controls, a document
list, selected-line editor, Apply/Insert/Delete/Reload/Save controls and a
status label. The script accepts only normalized paths below `/data/`, limits
one document to 32 lines and 32,512 bytes, rejects invalid UTF-8, and converts
CRLF/CR input to LF. The `fs.write_file` call is always made with
`atomic=true, fsync=true`; Save writes current lines, while Reload re-reads the
file and resets dirty state. The example declares no network or process
capability.

The final OrbStack GUI gate passed host Mica `24/24`, Editor pointer dispatch
for document/line/Apply/Save/Reload (`4, 5, 6, 10, 9`), ReadRange/WriteAtomic
completion, CloseRequested, endpoint reclamation and process status 0. The
serial trace contained two load markers and
`mica-editor saved ... bytes=44 atomic=true fsync=true`. Full-frame CRCs
pre/focused/typed/apply/saved/reload were
`3eeb31ac/5ea9fc60/dcccc6a3/da105c73/18f38838/7e895e1d`; the stable first-row
crop was `0a8ab59f` for both Apply and Reload.

## Serial and SSH commands

On the serial shell (`micro>`):

```text
mica -e 'print(40 + 2)'
mica
mica> print(6 * 7)
mica> exit
mica --allow fs.read:/data --allow fs.write:/data /data/example.mica -- arg1 arg2
mica --timeout 5s -e 'print(time.uptime())'
mica --gui --timeout 86400s --allow gui.window /mica/gui-counter.mica
```

The Mica file command must name an existing MFS path and its manifest is
intersected with the launcher policy. `run mica` prints `run: mica: not found`.
The serial shell itself also exposes `help`, `ps`, `uptime`, the complete
filesystem command set (`ls/list`, `cat/read`, `stat`, `touch/create`, `cp`,
`write`, `mkdir`, `rmdir`, `mv/rename`, `rm/remove/unlink`, `fsync`, `sync`),
`run`, `mica` and `shutdown`. Filesystem commands accept the same forms under
the explicit `fs` namespace, such as `fs stat /data/file`.

The serial shell also exposes a bounded curl-like GET client:

```text
curl -i https://example.com/
curl -s -o /data/response https://example.com/
```

It accepts HTTP/HTTPS URLs, reuses Mica's `net.browse` and TLS policy path, and
can atomically save a response with `-o`/`--output`. Responses are limited to
32 KiB; console output is UTF-8 only. This is intentionally a shell GET tool,
not a full POSIX `curl` implementation (no POST, redirects, or arbitrary
headers).

SSH uses the generated Ed25519 key and the fixed user `micro`:

```sh
make build
ssh -F /dev/null -T -p "${SSH_PORT:-2222}" \
  -i build/ssh/id_ed25519 -o IdentitiesOnly=yes \
  -o StrictHostKeyChecking=accept-new micro@127.0.0.1
```

SSH exec accepts `help`, `uptime`, `ps`, `clear`, `echo`, `exit`, and the Mica
forms (`mica -e`, `mica <path>`, `mica -- ...`). `mica` without an interactive
shell is rejected. The QEMU SSH gate additionally checks wrong-key and no-key
failures (exit 255), Mica eval/REPL/file/policy/disconnect, and a clean guest
shutdown.

## ABI and remaining boundaries

The script broker is `protocol::SCRIPT = 8`; netd is
`protocol::NETWORK = 9`. `process::Operation::SpawnScript = 6` allocates the
session region and `ThreadStartEx = 30` launches the Mica profile. The time
protocol numbers are `Sleep=1`, `Uptime=2`, `Realtime=3`; realtime is exposed
to user code through `ClockRealtime = 31` and reads PL031 seconds. The normal
TIME endpoint handles Sleep/Uptime; Mica/TLS use the direct realtime syscall.

The final repository still intentionally has these limits:

- no low-level TLS broker (`net.tls_connect` is NotSupported), HTTP/HTTPS is
  the only trusted TLS surface;
- no automatic redirects in the generic HTTP API, HTTP/2, proxy, cookies,
  WebSocket or streaming response API; the bundled Reader alone follows up to
  eight HTTP(S) redirects;
- one bounded session per Mica process, bounded sockets/transfers and buffered
  responses; no dynamic linking or disk ELF loading;
- no general capability delegation to scripts, raw device access, or arbitrary
  process control beyond named policy rules.
